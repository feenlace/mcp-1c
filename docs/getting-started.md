# Быстрый старт

Подключаем AI-ассистента к вашей базе 1С за 10 минут.

## Что это и зачем

**Проблема:** Вы пишете код на BSL в 1С. Современные AI-модели (YandexGPT, GigaChat, Claude и др.) умеют генерировать код, но не знают структуру *вашей* конфигурации — какие справочники, документы, реквизиты у вас есть. Без этого AI выдумывает несуществующие реквизиты и пишет нерабочий код.

**Решение:** mcp-1c — мост между AI-ассистентом и вашей базой 1С. После установки AI видит:
- Все объекты конфигурации (справочники, документы, регистры, ...)
- Реквизиты, табличные части, измерения, ресурсы
- Код модулей (через поиск по выгрузке конфигурации)
- Структуру форм
- Данные через запросы (только SELECT)

AI не просто «знает 1С вообще» — он знает *именно вашу* конфигурацию и пишет точный код под неё.

### Что такое MCP

MCP (Model Context Protocol) — открытый протокол, который позволяет AI-ассистентам обращаться к внешним источникам данных. Это стандарт, который поддерживают десятки AI-клиентов: [Claude Desktop](https://claude.ai/download), [Cursor](https://cursor.com), [Windsurf](https://codeium.com/windsurf) и другие. Полный список — на [modelcontextprotocol.io](https://modelcontextprotocol.io).

Вам не нужно разбираться в деталях протокола — просто установите mcp-1c и AI-ассистент получит доступ к вашей базе.

### Как это работает

```
┌─────────────────┐         ┌──────────────┐         ┌──────────────┐
│  AI-ассистент   │  stdio  │  mcp-1c.exe  │  HTTP   │  База 1С     │
│  (любой MCP-    │ ──────► │  (посредник) │ ──────► │  (расширение │
│   совместимый)  │ ◄────── │              │ ◄────── │  HTTP-сервис)│
└─────────────────┘         └──────────────┘         └──────────────┘
```

1. Вы задаёте вопрос AI про вашу конфигурацию
2. AI через mcp-1c запрашивает нужные метаданные из 1С
3. Получает реальную структуру и пишет код, который подходит именно вашей базе

## Требования

- **1С:Предприятие 8.3 или 8.5** (коммерческая или учебная версия)
- **AI-клиент с поддержкой MCP** — например [Claude Desktop](https://claude.ai/download), [Cursor](https://cursor.com), [Windsurf](https://windsurf.com), [VS Code](https://code.visualstudio.com) и другие (полный список — [ниже](#шаг-4-настроить-ai-клиент))
- **Windows** или **Linux** (на macOS HTTP-сервис 1С [не поддерживается](https://www.online-ufa.ru/content/articles/limit-1c-for-macos/), но mcp-1c и автоустановка работают)

> Учебную версию 1С можно скачать бесплатно: [uc1.1c.ru](https://uc1.1c.ru/uchebnaya-versiya-1s/)

## Установка

### Шаг 1. Скачать mcp-1c

Скачайте `mcp-1c.exe` (Windows) или `mcp-1c` (macOS/Linux) со страницы [Releases](../../releases).

> На macOS и Linux после скачивания дайте файлу право на исполнение: `chmod +x mcp-1c`

> Или соберите из исходников: `go build -o mcp-1c ./cmd/mcp-1c/`

### Шаг 2. Установить расширение в базу 1С

Расширение добавляет в вашу базу HTTP-сервис, через который mcp-1c получает данные. Оно **не меняет** вашу конфигурацию — это именно расширение.

**Автоматически (рекомендуется):**

```bash
# Windows
mcp-1c --install "C:\путь\к\вашей\базе"

# macOS / Linux
mcp-1c --install ~/Documents/InfoBase
```

Программа сама найдёт установленную платформу 1С, загрузит расширение и обновит конфигурацию БД.

> Если платформа установлена в нестандартную папку, укажите путь явно:
> `mcp-1c --install "путь_к_базе" --platform "/custom/path/to/1cv8"`
>
> Если версия платформы не определяется автоматически (нестандартный путь без номера версии), укажите её явно:
> `mcp-1c --install "путь_к_базе" --platform "/custom/path/to/1cv8" --platform-version 8.3.13`

> Если в базе настроена аутентификация для Конфигуратора (DESIGNER), укажите учётные данные:
> `mcp-1c --install "путь_к_базе" --db-user Admin --db-password пароль`

> **Клиент-серверная база (MS SQL, PostgreSQL).** Если база зарегистрирована на сервере 1С, добавьте флаг `--server` и укажите в `--install` строку подключения в формате `сервер\имя_базы`:
> ```bash
> mcp-1c --install "srv-1c\buh_prod" --server --db-user Admin --db-password pass
> ```

> Перед установкой закройте все сеансы 1С (Конфигуратор, Предприятие) для этой базы.

> **Доступ по ролям.** Вместе с расширением ставится роль `MCP_ОсновнаяРоль` с правами на HTTP-сервис. Пользователям с ролью «Полные права» дополнительных действий не требуется. Остальным пользователям роль нужно назначить вручную в Конфигураторе: **Администрирование → Пользователи**, нужный пользователь, вкладка **«Прочие»**. Расширение не назначает роль само и не меняет основные роли конфигурации. Без назначенной роли вызовы отвечают ошибкой доступа.

**Вручную (если автоматическая не сработала):**

1. Соберите .cfe из исходников (см. [Сборка расширения](../README.md#сборка-расширения-из-исходников))
2. Откройте базу в **Конфигураторе**
3. Меню **Конфигурация → Расширения конфигурации**
4. Нажмите **«Добавить из файла»** и выберите собранный `MCP_HTTPService.cfe`
5. Нажмите **F7** (обновить конфигурацию базы данных)
6. Назначьте роль `MCP_ОсновнаяРоль` вручную тем пользователям, которые будут работать через MCP: **Администрирование → Пользователи**, нужный пользователь, вкладка **«Прочие»**. Пользователям с ролью «Полные права» это не нужно

### Шаг 3. Запустить HTTP-сервис 1С

Чтобы mcp-1c мог обращаться к базе, нужно опубликовать HTTP-сервис 1С.

#### Публикация через Apache или IIS

Стандартный способ публикации HTTP-сервисов 1С. Работает на **Windows** (IIS или Apache) и **Linux** (Apache или ibsrv). Подходит как для разработки, так и для постоянной работы.

1. Откройте базу в **Конфигураторе от администратора**
2. **Администрирование → Публикация на веб-сервере**
3. Укажите имя (например `base`). На вкладке **HTTP-сервисы** включите опцию **«Публиковать HTTP-сервисы расширений по умолчанию»**. MCPService поставляется в расширении и в общем списке сервисов не отображается, это штатное поведение платформы 1С.
4. Нажмите **Опубликовать**

URL в этом случае: `http://localhost/base/hs/mcp-1c`

> **Linux:** Конфигуратор в Linux не видит веб-серверы, поэтому публикуйте утилитой `webinst`, а HTTP-сервис расширения добавьте в `default.vrd` (опция «Публиковать HTTP-сервисы расширений по умолчанию» либо явный блок `service name="MCPService"`). После повторной публикации запись в `default.vrd` нужно добавить заново. Подробнее в [настройке 1С](1c-setup.md#шаг-4-запустить-http-сервис-1с).

#### Платформенные ограничения

**macOS:** Платформа 1С [не поддерживает HTTP-сервисы на macOS](https://www.online-ufa.ru/content/articles/limit-1c-for-macos/). Используйте Windows (можно в виртуальной машине, например UTM).

**Linux:** Используйте публикацию через Apache или автономный сервер ibsrv.

#### Проверка

Откройте в браузере или выполните в терминале:

```bash
curl http://localhost/base/hs/mcp-1c/version
```

Ожидаемый ответ:
```json
{"version":"0.4.7"}
```

Если видите ответ — HTTP-сервис 1С работает, переходите к шагу 4.

Этой сборке mcp-1c нужно расширение версии 0.4.7 или новее. Более старое расширение запуску не мешает: сервер стартует и продолжает работать, но при старте пишет в журнал строку `Extension is OLDER than this build requires`, и инструменты, которым нужны появившиеся позже методы, будут отвечать ошибкой. Обновить расширение можно командой из шага 2. Расширение новее 0.4.7 это штатное сочетание, его ставят платные версии.

#### Claude Desktop

[Claude Desktop](https://claude.ai/download) — десктопное приложение от Anthropic.

**Файл конфигурации:**

- **Windows:** `%APPDATA%\Claude\claude_desktop_config.json`
- **macOS:** `~/Library/Application Support/Claude/claude_desktop_config.json`

Если файла нет — создайте его. Добавьте:

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": ["--base", "http://localhost:8080/hs/mcp-1c"]
    }
  }
}
```

**Перезапустите** Claude Desktop (полностью закройте и откройте заново).

> **Режим доступа инструментов.**
> По умолчанию Claude Desktop загружает инструменты «по запросу» (Auto) — при большом количестве подключённых серверов это экономит контекст, но может приводить к тому, что часть инструментов mcp-1c не обнаруживается при поиске. Если вы используете только mcp-1c (или 1-2 коннектора), рекомендуем переключить режим на **Always Available**:
>
> **«+» → Connectors → Tool access → Always available**
>
> В этом режиме все 11 инструментов загружаются сразу и AI видит их целиком.

#### Claude Code (CLI)

[Claude Code](https://docs.anthropic.com/en/docs/claude-code) — консольный AI-ассистент от Anthropic. Работает в терминале.

Добавьте MCP-сервер командой:

**Windows:**
```cmd
claude mcp add 1c --transport stdio -- cmd /c C:\путь\к\mcp-1c.exe --base http://localhost:8080/hs/mcp-1c
```

**macOS / Linux:**
```bash
claude mcp add 1c --transport stdio -- /путь/к/mcp-1c --base http://localhost:8080/hs/mcp-1c
```

> По умолчанию сервер добавляется в текущий проект. Чтобы сделать его доступным во всех проектах, добавьте `--scope user`:
> ```bash
> claude mcp add 1c --scope user --transport stdio -- /путь/к/mcp-1c --base http://localhost:8080/hs/mcp-1c
> ```

Проверить, что сервер добавлен:

```bash
claude mcp list
```

Удалить сервер:

```bash
claude mcp remove 1c
```

#### VS Code + GitHub Copilot

[VS Code](https://code.visualstudio.com) с расширением [GitHub Copilot](https://marketplace.visualstudio.com/items?itemName=GitHub.copilot) поддерживает MCP-серверы начиная с версии VS Code 1.99.

> MCP-инструменты работают только в режиме **Agent** в чате Copilot. Убедитесь, что выбран Agent, а не Chat или Edit.

**Файл конфигурации:**

- **Для конкретного проекта:** `.vscode/mcp.json` в корне проекта
- **Глобально:** выполните команду **MCP: Open User Configuration** в Command Palette (`Ctrl+Shift+P`)

Создайте файл `.vscode/mcp.json` и добавьте:

```json
{
  "servers": {
    "1c": {
      "type": "stdio",
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": ["--base", "http://localhost:8080/hs/mcp-1c"]
    }
  }
}
```

> **Формат отличается от Claude Desktop:** ключ верхнего уровня — `"servers"` (не `"mcpServers"`), и для каждого сервера нужно указать `"type": "stdio"`.

Или добавьте через интерфейс: **Command Palette → MCP: Add Server → stdio**.

## Поиск по коду конфигурации (--dump)

Инструмент `search_code` работает по локальной выгрузке конфигурации в файлы. Чтобы включить его:

1. Выгрузите конфигурацию через Конфигуратор: **Конфигурация -> Выгрузить конфигурацию в файлы**
2. Добавьте флаг `--dump` с путём к выгрузке:

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": [
        "--base", "http://localhost:8080/hs/mcp-1c",
        "--dump", "C:\\путь\\к\\выгрузке"
      ]
    }
  }
}
```

Без флага `--dump` инструменты `search_code` и `reload_dump` не будут доступны.

### Повторная выгрузка без перезапуска

Индекс поиска строится один раз, при запуске сервера. Если выгрузить конфигурацию заново, пока сервер работает, `search_code` продолжит отвечать по прежнему состоянию: новые модули не найдутся, а в режиме `smart` останутся удалённые и старые версии изменённых.

Инструмент `reload_dump` перечитывает выгрузку без перезапуска. Аргументов у него нет: он сам сверяет каталог выгрузки по относительному пути, времени изменения и размеру каждого файла `.bsl`, и перестраивает индекс, только если что-то изменилось.

Перестроение занимает столько же времени, сколько и первая индексация, потому что индекс строится заново целиком. Выигрыш не в скорости, а в том, что перезапускать сервер и переподключать MCP-клиент не нужно, и что всё это время поиск продолжает отвечать по прежнему состоянию: новый индекс подключается одним переключением в самом конце.

### Режимы поиска

`search_code` поддерживает три режима:

| Режим | Описание |
|-------|---------|
| `smart` | Полнотекстовый поиск с BM25-ранжированием (по умолчанию). Результаты отсортированы по релевантности. |
| `regex` | Регулярное выражение (синтаксис Go regexp). |
| `exact` | Точная подстрока, регистронезависимый поиск. |

**BSL-синонимы.** В режиме `smart` работает автоматическое расширение запроса: поиск по английским именам функций находит русские и наоборот. Например, `StrFind` найдёт модули с `СтрНайти`, а `Процедура` — модули с `Procedure`.

**Фильтрация.** Можно ограничить поиск по типу метаданных (`category`: Документ, Справочник, ОбщийМодуль и т.д.) и типу модуля (`module`: МодульОбъекта, МодульМенеджера, МодульФормы и т.д.).

### Неблокирующий запуск

При старте с `--dump` MCP-сервер доступен сразу — индекс строится в фоне. Пока индексация не завершена, `search_code` вернёт сообщение «search index is building, please retry». Для конфигураций с 13 000+ модулей первая индексация занимает ~7 секунд (шардированная параллельная сборка по числу ядер CPU).

### Кеширование индекса

Построенный индекс автоматически сохраняется на диск. При следующих запусках загружается из кеша — старт практически мгновенный.

**Расположение кеша:**

| ОС | Путь |
|----|------|
| macOS | `~/Library/Caches/mcp-1c/` |
| Linux | `~/.cache/mcp-1c/` |
| Windows | `%LocalAppData%\mcp-1c\` |

Размер кеша зависит от конфигурации и обычно составляет ~100-200 МБ для крупных конфигураций.

### Принудительная перестройка индекса (--reindex)

Флаг `--reindex` заставляет mcp-1c заново построить поисковый индекс, игнорируя кеш.

Обновление выгрузки этого флага не требует. Кеш привязан к содержимому выгрузки, поэтому при обычном запуске mcp-1c сам замечает изменившиеся, добавленные и удалённые модули и строит индекс заново. После нового `DumpConfigToFiles` достаточно перезапустить MCP-сервер.

Флаг нужен, когда индекс работает некорректно или повреждён: он пересобирает кеш при том же содержимом выгрузки.

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": [
        "--base", "http://localhost:8080/hs/mcp-1c",
        "--dump", "C:\\путь\\к\\выгрузке",
        "--reindex"
      ]
    }
  }
}
```

> После перестройки индекса флаг `--reindex` можно убрать — при следующих запусках будет использоваться обновлённый кеш.

## Аутентификация

Если в базе 1С настроена аутентификация для HTTP-сервисов, добавьте параметры `--user` и `--password`. Примеры ниже показаны для формата Claude Desktop / Cursor / Windsurf (`"mcpServers"`). Для VS Code + Copilot используйте формат `"servers"` (см. [выше](#vs-code--github-copilot)).

> **Передавайте логин и пароль флагами `--user` и `--password`, а не внутри адреса.** В `--base` оставляйте только адрес публикации: `http://localhost:8080/hs/mcp-1c`. Запись вида `http://Admin:secret@localhost:8080/hs/mcp-1c` тоже работает, но у неё есть цена: пароль виден в конфиге AI-клиента и в списке процессов, а часть таких адресов mcp-1c отклоняет при запуске. Русские буквы в логине или пароле внутри адреса отклоняются всегда, а флагам `--user` и `--password` они не мешают. Разбор форм адреса собран в разделе [Адрес HTTP-сервиса в --base](#адрес-http-сервиса-в---base).

Указывайте оба параметра сразу. `--user` без `--password` это не «вход без пароля»: на сервер уходит HTTP Basic с пустым паролем, и база с заданным паролем ответит 401. Одного `--user` достаточно только тогда, когда пароль у пользователя действительно пустой.

**Через аргументы:**

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": [
        "--base", "http://localhost:8080/hs/mcp-1c",
        "--user", "Admin",
        "--password", "пароль"
      ]
    }
  }
}
```

**Через переменные окружения:**

```json
{
  "mcpServers": {
    "1c": {
      "command": "C:\\путь\\к\\mcp-1c.exe",
      "args": ["--base", "http://localhost:8080/hs/mcp-1c"],
      "env": {
        "MCP_1C_USER": "Admin",
        "MCP_1C_PASSWORD": "пароль"
      }
    }
  }
}
```

**Claude Code (CLI):**

```bash
claude mcp add 1c --transport stdio -e MCP_1C_USER=Admin -e MCP_1C_PASSWORD=пароль -- /путь/к/mcp-1c --base http://localhost:8080/hs/mcp-1c
```

## Адрес HTTP-сервиса в --base

В `--base` указывают корневой адрес публикации HTTP-сервиса, например `http://localhost:8080/hs/mcp-1c`. К нему mcp-1c дописывает имя метода (`/version`, `/metadata`, `/query` и другие), поэтому адрес должен заканчиваться на корне сервиса. То же значение можно задать переменной `MCP_1C_BASE_URL`; флаг имеет приоритет над переменной.

### Логин и пароль внутри адреса

Адрес вида `http://Admin:secret@localhost:8080/hs/mcp-1c` принимается. При создании клиента mcp-1c снимает с адреса логин и пароль и хранит их отдельно от него: дальше они уходят только в заголовок HTTP Basic, а сам адрес остаётся без них. Поэтому ни в тексте ошибки, ни в журнале, ни в ответе модели пароль не появляется: там показывается только схема и хост, например `http://localhost:8080`.

Если задан `--user`, учётные данные из адреса не используются: побеждает флаг.

Русские буквы внутри адреса не разрешены ни в логине, ни в пароле: адрес `http://Админ:пароль@localhost:8080/hs/mcp-1c` отклоняется. Записать их в адрес можно только процентным кодированием UTF-8, а такую строку невозможно прочитать глазами. Флагам `--user` и `--password` русские буквы не мешают, поэтому задавайте их флагами.

### Какие адреса отклоняются при запуске

Часть адресов читается двумя способами сразу, и выбрать между ними нельзя. Такой адрес mcp-1c отклоняет при запуске: сервер не стартует, а причина печатается в stderr. В сообщении нет ни одного символа самого адреса, поэтому его можно приложить к обращению в поддержку.

| Адрес в `--base` | Результат |
|------------------|-----------|
| `http://Admin:p@ssw0rd@localhost:8080/hs/mcp-1c` | Принимается. Разделителем считается последняя `@`, поэтому пароль `p@ssw0rd` разбирается целиком |
| `http://localhost/base/hs/mcp-1c@v2` | Принимается. `@` в пути это допустимый символ имени сервиса 1С |
| `http://localhost:8080/base/hs/mcp-1c@v2` | Отклоняется. Тот же адрес, но с явным портом, читается двояко (см. ниже про двоеточие). Запишите `@` как `%40` |
| `http://localhost:8080/hs/mcp-1c?debug=1` | Отклоняется. К адресу дописывается имя метода, поэтому всё после `?` или `#` ломает запрос |
| `http://Admin:pass/word@localhost:8080/hs/mcp-1c` | Отклоняется. `/` в пароле обрывает адрес. Запишите `/` как `%2F` |
| `http://Админ:пароль@localhost:8080/hs/mcp-1c` | Отклоняется. Русские буквы в логине или пароле внутри адреса не разбираются. Задайте их флагами `--user` и `--password` |

Выход называет само сообщение. Если в адресе есть логин и пароль, уберите их оттуда и задайте флагами `--user` и `--password`, а в самом адресе оставьте только корень HTTP-сервиса, без `?` и `#`. Если логин и пароль обязаны остаться в адресе, закодируйте служебные символы внутри них: `@` как `%40`, `/` как `%2F`, `?` как `%3F`, `#` как `%23`. Например, `http://Admin:pass%2Fword@localhost:8080/hs/mcp-1c` принимается, и пароль восстанавливается как `pass/word`.

**Про двоеточие перед `@`.** Сообщение об отказе называет два места, где это двоеточие стоит: перед номером порта или в самом пути. Для адреса с явным портом это двоеточие порта: в `http://localhost:8080/base/hs/mcp-1c@v2` в пути двоеточия нет вовсе. Правило короче, чем сообщение: если в пути есть `@` и в адресе указан порт, запишите `@` как `%40`. Без явного порта тот же адрес принимается.

**Если в адресе есть и учётные данные, и `?`.** Адрес `http://Admin:secret@localhost:8080/hs/mcp-1c?debug=1` отклоняется один раз, но исправить в нём нужно две вещи, и обе названы в сообщении: перенести логин и пароль во флаги `--user` и `--password` и убрать всё, начиная с `?`. Если убрать только логин и пароль, адрес будет отклонён снова, уже из-за `?`.

**Опечатка в адресе при запуске не ловится.** Проверке подлежат только адреса со знаками `@`, `?` или `#`. Всё остальное mcp-1c берёт как записано: `http://localhost:8080/hs/mcp -1c` с лишним пробелом стартует нормально, и вы увидите не отказ при запуске, а ошибку соединения при первом обращении к 1С. Четвёртое сообщение, «адрес 1С отклонён: в нём есть ? или #, и разобрать его как адрес не получается», достаётся адресам, которые содержат `?` или `#` и вдобавок записаны с ошибкой, например `http://localhost:80 80/hs/mcp-1c?x=1`. Про пробел оно не говорит, и не может: адрес с пробелом, но без `@`, `?` и `#` до разбора не доходит и принимается как есть.

### Перенаправления

mcp-1c идёт по перенаправлению (коды 301, 302, 303, 307, 308) только в пределах адреса из `--base`: та же схема, тот же хост, тот же порт. Перенаправление на другую схему, другой хост или другой порт не выполняется. Ответ 30x возвращается как ошибка `1C returned status 302 ...`, тело такого ответа модели не показывается, и логин с паролем на чужой адрес не уходят.

Что это значит на практике: если веб-сервер переадресует `http` на `https` или на другой порт, укажите в `--base` конечный адрес. Прежние сборки шли по такому перенаправлению, и на другой порт или на другую схему того же хоста заголовок с логином и паролем уходил вместе с запросом.

## Ограничения MCP-клиентов

Разные AI-клиенты по-разному работают с MCP-инструментами. У mcp-1c всего 11 инструментов, поэтому перечисленные ограничения обычно не создают проблем, но полезно знать о них, если вы подключаете несколько MCP-серверов.

| Клиент | Ограничение | Рекомендация |
|--------|------------|--------------|
| **Claude Desktop** | В режиме Auto загружает инструменты «по запросу» и может не найти часть из них | Включите **Always Available** (см. [инструкцию](#claude-desktop)) |
| **Cursor** | Оптимально до ~40 инструментов суммарно по всем серверам | Отключайте серверы, которые не используете |
| **Windsurf** | Лимит 100 инструментов суммарно по всем серверам | Управляйте через иконку MCPs в панели Cascade |
| **VS Code + Copilot** | MCP работает только в режиме Agent | Переключите режим чата на Agent |
| **Continue** | MCP работает только в режиме Agent | Переключите режим чата на Agent |
| **JetBrains** | Требуется подписка AI Assistant | Включите режим Codebase в чате AI Assistant |

## Устранение неполадок

**«1C platform not found» при --install**
Платформа 1С не найдена в стандартных папках. Укажите путь явно: `mcp-1c --install "путь" --platform "/path/to/1cv8"`. Если версия не определяется из пути, добавьте `--platform-version 8.3.13` (укажите вашу версию). Минимальная поддерживаемая версия: 8.3.10.

**«Файл не найден» при --install**
Проверьте путь к базе. Это папка, в которой лежит файл `1Cv8.1CD`.

**«connection refused» при curl**
HTTP-сервис 1С недоступен. Проверьте, что веб-сервер (Apache или IIS) запущен и публикация базы активна.

**«404» при обращении к /hs/mcp-1c/...**
- Расширение не установлено или не активно. Проверьте: Конфигуратор → Расширения → галочка «Активно» напротив MCP_HTTPService.
- Конфигурация БД не обновлена. Нажмите F7 в Конфигураторе.

**«401» при обращении к /hs/mcp-1c/...**
- Указан `--user` без `--password`. Это не «без пароля»: уходит Basic с пустым паролем, и при заданном пароле вы получите тот же 401. Указывайте оба параметра либо переменные `MCP_1C_USER` и `MCP_1C_PASSWORD`. Если пароль пустой, хватит одного `--user`, а если логин и пароль прописаны в `ib=` в `default.vrd`, не указывайте ни того, ни другого.
- Проверьте доступ вручную: `curl -u "Пользователь:пароль" http://localhost/MyBase/hs/mcp-1c/version`. Открывающаяся в браузере база доступность HTTP-сервиса не подтверждает: у веб-клиента своя форма входа, а сервис ждёт HTTP Basic.
- На IIS (обычно подкод 401.5) в разделе Authentication анонимная проверка подлинности должна быть включена, а обычная (Basic) и Windows выключены, иначе IIS перехватит заголовок Authorization. Права: IIS_IUSRS на каталог платформы, IUSR на каталог файловой базы.

**«адрес 1С … отклонён» при запуске, сервер не стартует**
mcp-1c не принял значение `--base` или `MCP_1C_BASE_URL`. Причину называет само сообщение, а разбор форм адреса и способы обхода собраны в разделе [Адрес HTTP-сервиса в --base](#адрес-http-сервиса-в---base). Чаще всего помогает убрать логин и пароль из адреса и задать их флагами `--user` и `--password`.

**«1C returned status 302» (а также 301, 303, 307, 308)**
Веб-сервер отвечает перенаправлением, а mcp-1c идёт по нему только в пределах адреса из `--base`. Обычно это переадресация `http` на `https` или на другой порт. Укажите в `--base` тот адрес, на который переадресует веб-сервер.

**«Extension is OLDER than this build requires» в журнале**
Расширение в базе старее 0.4.7. Сервер продолжает работать, но инструменты, которым нужны появившиеся позже методы, будут отвечать ошибкой. Переустановите расширение: `mcp-1c --install "путь\к\базе"`.

**«address already in use»**
Порт веб-сервера занят другим процессом. Освободите порт или настройте веб-сервер на другой порт и обновите URL в конфиге AI-клиента.

**AI не видит инструменты 1С**
- Убедитесь, что AI-клиент перезапущен после изменения конфига.
- Проверьте JSON на ошибки (лишние/недостающие запятые, неэкранированные слеши).
- Убедитесь, что путь к `mcp-1c.exe` правильный и полный (абсолютный, не относительный).

**AI не находит нужный инструмент (например get_object_structure)**
- В Claude Desktop: **«+» → Connectors → Tool access → Always available**. В режиме Auto (по умолчанию) Claude загружает инструменты «по запросу» и может не найти нужный.
- В Cursor / Windsurf: проверьте, что сервер 1c включён и все его инструменты активны в настройках MCP.

**MCP-сервер не запускается в VS Code + Copilot**
- Убедитесь, что VS Code версии 1.99 или выше.
- Убедитесь, что в чате Copilot выбран режим **Agent** (не Chat и не Edit).
- Проверьте формат: в `.vscode/mcp.json` ключ верхнего уровня — `"servers"` (не `"mcpServers"`), и для каждого сервера указан `"type": "stdio"`.

**MCP-сервер не работает в JetBrains IDE**
- Убедитесь, что IDE версии 2025.1 или выше.
- Проверьте: **Settings → Tools → AI Assistant → Model Context Protocol (MCP)** — сервер должен быть в списке и включён.
- Если вы импортировали конфигурацию из Claude Desktop — включите опцию **Automatically enable new and changed MCP servers**.

**«Достигнуто ограничение учебной версии» / «Предельное количество подключений»**
- Учебная версия 1С ограничивает количество одновременных подключений. Закройте лишние сеансы (Конфигуратор, другие окна 1С). mcp-1c закрывает HTTP-соединения после каждого запроса, чтобы минимизировать эту проблему.
